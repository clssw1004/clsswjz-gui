# 2026-08-24 工作日志

## 经期记录共享只读查看（83 测试全过，analyze 0 问题）

背景：经期记录纳入数据共享，被分享用户只能只读。参考油耗记录（fuelRecord 仅共享开关、无独立只读页；经期是第一个实现完整"查看他人只读"的模块）。

调研结论（Explore agent）：共享只读不是设备间推数据，而是从被分享者 B 本地库按 `createdBy` 过滤读取。B 能查到 A 的 periodCycle 当且仅当服务端 pull 已把 A 数据同步进 B 库（依赖 user_share 订阅式同步，客户端不强推）。本仓库为客户端，UI/DAO 层已就绪。

### 实现
1. **共享模块注册**：`share_settings_page._modules` 加入 `periodCycle`（图标 water_drop，label 用 `periodRecord`），owner 可把经期分享给他人。
2. **AppConfigManager**：新增 `periodViewUserId` 持久化（key `period_view_user_id`），含 setter 与构造恢复。
3. **PeriodRecordProvider**：
   - 新增 `_viewUserId`/`currentUserId`/`isReadOnly`，`setViewUserId`（默认持久化）、`applyViewUserId`（仅恢复不写回，供 initState）
   - `loadRecords` 及所有读写方法改用 `currentUserId`（查看用户优先）
   - 写操作（startPeriod/endPeriod/backfillPeriod/deleteCycle/deleteDailyRecord/upsertDailyRecord）入口加 `if (isReadOnly) return`
4. **PeriodUserSelector**（新文件，周期页 AppBar title）：仿 BookSelector，点击弹抽屉列出"我的经期记录" + 共享给我的经期 owner（SharedModuleProvider.getSharedBy('periodCycle') 加载 owner 头像昵称），选中持久化。SharedModuleProvider 用可空 watch 容错（测试环境无该 provider 不崩溃）。
5. **period_calendar_page**：
   - initState 从 AppConfigManager 恢复查看用户后再 loadRecords
   - `_checkOnboarding` 与 `_handleStartPeriod` 只读时跳过/禁用
   - `_buildBottomActionPanel` 只读时仅显示 lock 提示条，不渲染任何增删改
   - hero 卡只读时不传 onStartPeriod
6. **l10n**：新增 readOnly/myPeriodRecord/periodViewUser/periodViewSelfHint/periodReadOnlyHint/noSharedPeriodData（3 arb + gen-l10n）

### 依赖注意（服务端联动）
- 本客户端实现完成只读查看 UI。但 B 本地要有 A 的周期数据，需服务端按 user_share 把 A 的 `periodCycle`/`periodDailyRecord` 日志投递到 B 的 pull（订阅式同步）。若服务端未投递，B 切换查看用户后将查不到数据（空日历）。这是与服务端联调的关键点。
- fuelRecord 若要同样支持只读查看，需补 `viewUserId` 切换 + `findByCreatorOrShared` DAO（本期未做）。
