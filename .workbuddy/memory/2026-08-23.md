# 2026-08-23

## 修复：同步时 user 表不包含同账本其他成员的数据（clsswjz-server）

**现象**：客户端同步后本地 user 表只有自己，账本成员/创建者/更新人的用户名无法翻译（显示 userId 或空白）。涉及 gui 端 `account_book_service.dart`（`userMap[m.userId]?.nickname`）、`vo_transfer.dart`（createdByName/updatedByName）、`statistic_service.dart`。

**根因**：`SyncService.pull()` 的可见范围（sync.service.ts:238-256）只含「自己操作的日志 + 自己账本(book)域日志 + 关于自己的 bookMember 事件」，而 USER 日志的 `parentType='root'`，其他用户的 user 日志永远不可见。佐证：`desensitize()` 专门为「其他用户 USER 日志」脱敏，说明设计上本就预期下发，是可见范围漏实现。

**修复**（sync.service.ts）：
- `pull()` 可见范围新增一条：`business_type='user' AND operator_id IN (同账本成员 userIds)`
- 新增 `getBookMemberIds(bookIds)`：查 account_books.created_by ∪ rel_accountbook_user.user_id
- 关键坑：query builder `select()` 必须用 propertyName（`book.createdBy`/`rel.userId`），用列名（`book.created_by`）返回 key 是列名导致取值 undefined
- 敏感字段由既有 `desensitize()` 脱敏（username/password/phone/email → `<secret>`），nickname/avatar 保留

**测试**：sync.service.spec.ts 新增 3 用例（同账本成员 user 日志互相可见 / 无关用户不可见 / 脱敏），14 suites 89 tests 全过。gui 端 user 表 username 无唯一约束，`<secret>` 不会冲突，无需客户端改动。

**语义约定**：A、B 只要在同一账本（创建者或成员），彼此的 user 资料日志即互相可见。
